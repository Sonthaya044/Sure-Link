# SureLink

SureLink คือเว็บแอปพลิเคชันสำหรับตรวจสอบความปลอดภัยของ URL โดยใช้ VirusTotal API เป็นแหล่งข้อมูลหลักเพื่อประเมินว่า URL ที่ผู้ใช้ป้อนเข้ามานั้นมีความเสี่ยงเป็น phishing, malware, suspicious หรือไม่

## ภาพรวมของโปรเจกต์
ผู้ใช้กรอก URL ลงในหน้าเว็บ ระบบจะทำการประมวลผลและแสดงผลลัพธ์บนหน้า dashboard โดยแยกระดับความเสี่ยงออกเป็น:
- High
- Medium
- Low

ระบบยังมีฟีเจอร์เก็บผลการสแกนไว้ในฐานข้อมูล SQLite เพื่อให้สามารถนำกลับมาใช้ซ้ำในวันเดียวกัน และเพื่อให้แสดงผล analytics ได้อย่างรวดเร็ว

## วัตถุประสงค์ของระบบ
- ตรวจสอบความปลอดภัยของ URL
- แสดงผลลัพธ์แบบเข้าใจง่ายผ่านหน้าเว็บ
- เก็บผลสแกนไว้เพื่อใช้ซ้ำและวิเคราะห์สถิติ
- ลดการเรียก VirusTotal API ซ้ำในวันเดียวกัน

## กระบวนการทำงาน
1. ผู้ใช้ป้อน URL ผ่านหน้าเว็บ
2. ระบบจะตรวจว่า URL นั้นมีข้อมูลในฐานข้อมูล SQLite อยู่หรือไม่
3. ถ้ามีข้อมูลและยังอยู่ในช่วง 1 วัน จะใช้ข้อมูลจาก DB กลับมาเลย
4. ถ้าไม่มีข้อมูลใน DB หรือข้อมูลเก่าเกิน 1 วัน ระบบจะเรียก VirusTotal API เพื่อสแกนใหม่
5. ผลลัพธ์ใหม่จะถูกบันทึกลงฐานข้อมูลและเขียนทับข้อมูลเดิมในแถวเดียวกัน

## การจัดเก็บข้อมูล
ระบบใช้ SQLite เป็นฐานข้อมูลฝั่งเซิร์ฟเวอร์ โดยเก็บข้อมูลไว้ในไฟล์ชื่อ `securescan.db`

### ตารางหลัก: `url_cache`
ตารางนี้เก็บข้อมูลผลสแกนของแต่ละ URL โดยมีฟิลด์หลักดังนี้:
- `id` : รหัสหลักของแถวข้อมูล
- `url` : URL ที่สแกน
- `domain` : โดเมนของ URL
- `tier` : ระดับความเสี่ยง (High / Medium / Low)
- `malicious_count` : จำนวนผลลัพธ์ที่ถูกจัดว่า malicious
- `raw_data` : ข้อมูลผลลัพธ์ดิบจาก VirusTotal ในรูปแบบ JSON
- `scanned_timestamp` : เวลาที่สแกนล่าสุด
- `scan_count` : จำนวนครั้งที่ URL นี้ถูกสแกน

### พฤติกรรมของ DB / Cache
- สแกนครั้งแรก → บันทึกผลลง DB
- สแกนซ้ำในวันเดียวกัน → ใช้ข้อมูลจาก DB กลับมาเลย
- สแกนซ้ำในวันถัดไป → จะไม่ใช้ข้อมูลเก่าอีก และจะเรียก API ใหม่
- ผลลัพธ์ใหม่จะเขียนทับข้อมูลเดิมใน DB โดยอัปเดต `scanned_timestamp` และข้อมูลล่าสุด

## การเก็บประวัติในหน้าเว็บ
นอกจากการเก็บผลสแกนไว้ใน SQLite แล้ว หน้าเว็บยังใช้ `localStorage` ในเบราว์เซอร์เพื่อเก็บประวัติการสแกนล่าสุดสำหรับการแสดงผลในหน้า History โดยข้อมูลจะถูกเก็บไว้ใน key ชื่อ `scanHistory`

> หมายเหตุ: `localStorage` เป็นข้อมูลฝั่งเบราว์เซอร์เท่านั้น ไม่ใช่ฐานข้อมูลหลักของระบบ

## ข้อกำหนดเบื้องต้น
- Python 3.10 ขึ้นไป
- ติดตั้ง dependency จากไฟล์ `requirements.txt`

## การติดตั้ง
1. ไปที่โฟลเดอร์โปรเจกต์
2. ติดตั้งไลบรารีที่จำเป็น

```bash
pip install -r requirements.txt
```

3. สร้างไฟล์ `.env` ในโฟลเดอร์โปรเจกต์
4. ใส่ค่า VirusTotal API Key ในไฟล์ `.env`

```env
VT_API_KEY=your_api_key_here
```

## วิธีรันแอป
รันคำสั่งต่อไปนี้:

```bash
python app.py
```

จากนั้นเปิดบราวเซอร์ไปที่:

```text
http://127.0.0.1:5000/
```

## โครงสร้างโฟลเดอร์หลัก
- `app.py` : แอป Flask หลักที่รวม routing, database initialization, scan logic และ API endpoint
- `blueprints/` : โมดูลย่อยสำหรับแยกฟังก์ชันออกเป็นส่วน ๆ
  - `scan.py` : ฟังก์ชันสแกน URL และการจัดเก็บผลใน DB
  - `api.py` : endpoint สำหรับ analytics และข้อมูลสถิติ
  - `core.py` : route สำหรับหน้าเว็บหลักและหน้า history
- `templates/` : ไฟล์ HTML ของหน้าเว็บ
  - `home.html` : หน้าแรกสำหรับป้อน URL
  - `dashboard.html` : หน้ารายงานผลการสแกน
  - `history.html` : หน้าประวัติการสแกน
- `static/` : ไฟล์ frontend
  - `js/home.js` : logic ของหน้าแรก
  - `js/dashboard.js` : logic สำหรับแสดงผล dashboard และบันทึกประวัติ
  - `js/history.js` : logic สำหรับแสดงและล้างประวัติ
- `requirements.txt` : รายการ dependency ของโปรเจกต์
- `vercel.json` : การตั้งค่า deployment บน Vercel

## ฟังก์ชันสำคัญในโค้ด
### `app.py`
- กำหนดค่า Flask และ logging
- ตั้งค่า Database Path
- สร้างตาราง `url_cache` หากยังไม่มี
- สร้างฟังก์ชันสำหรับค้นหาใน DB (`search_db`)
- สร้างฟังก์ชันสำหรับเรียก VirusTotal API (`scan_with_virustotal`)
- สร้างฟังก์ชันสำหรับบันทึกข้อมูลลง DB (`save_to_db`)
- สร้าง route สำหรับสแกน URL และแสดงผล

### `blueprints/scan.py`
- ให้บริการสำหรับจัดการการสแกน URL
- ดึงข้อมูลจาก DB ถ้ามีและยังใหม่อยู่
- ถ้าเก่ากว่า 1 วัน จะเรียก API ใหม่
- บันทึกผลลง DB ด้วยข้อมูลล่าสุด

### `blueprints/api.py`
- จัดเตรียมข้อมูลสำหรับ analytics เช่น
  - จำนวนสแกนทั้งหมด
  - จำนวนตามระดับความเสี่ยง
  - โดเมนที่ถูกสแกนบ่อยที่สุด
  - URL ที่ถูกสแกนบ่อยที่สุด
  - กลุ่มภัยคุกคามที่พบบ่อย

## ตัวอย่างการทำงาน
ตัวอย่างลำดับการทำงานสำหรับ URL เช่น `https://google.com`:
1. ผู้ใช้สแกน URL นี้เป็นครั้งแรก
2. ระบบเรียก VirusTotal API
3. ผลลัพธ์ถูกบันทึกลง `securescan.db`
4. ถ้าผู้ใช้สแกน `https://google.com` ซ้ำในวันเดียวกัน ระบบจะโหลดจาก DB โดยไม่ต้องเรียก API
5. ถ้าผู้ใช้สแกนซ้ำในวันถัดไป ระบบจะเรียก API ใหม่และเขียนทับผลเก่าใน DB

## หมายเหตุสำหรับนักพัฒนา
- หากต้องการให้ระบบใช้ข้อมูลจาก DB นานขึ้น หรือสั้นลง สามารถปรับค่าในฟังก์ชัน `search_db` ได้
- หากต้องการให้ระบบลบข้อมูลเก่าทิ้งอัตโนมัติ สามารถเพิ่ม logic สำหรับ cleanup DB ได้ในอนาคต
- หากลืมใส่ `VT_API_KEY` การสแกนจะล้มเหลว

## ปัญหาที่อาจเกิดขึ้น
- ไม่มีไฟล์ `.env` หรือไม่มี `VT_API_KEY` → การสแกนจะล้มเหลว
- ไม่มี dependency ที่ติดตั้งครบ → รันแอปไม่ได้
- Port 5000 ถูกใช้งานอยู่แล้ว → ต้องปิดโปรเซสเดิมก่อนหรือเปลี่ยน port

## คำแนะนำเพิ่มเติม
- ใช้ virtual environment เพื่อความสะดวกและไม่ทับ environment ของระบบ
- สำหรับการพัฒนาในอนาคต แนะนำให้ย้ายจาก `localStorage` เป็นฐานข้อมูลฝั่งเซิร์ฟเวอร์จริงสำหรับประวัติทั้งหมด เพื่อให้ประวัติแชร์กันได้ทุกอุปกรณ์
